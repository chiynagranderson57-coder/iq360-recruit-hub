  database correction for canonical project lqthjvzjkbwtggrhgpts.

- [production correction plan](./PRODUCTION_CORRECTION_PLAN.md): remaining
  execution gates, release ordering, recovery limits, and scope decisions.

The SQL creates the bounded private assignment helper, replaces recursive
athlete_access SELECT evaluation, removes four unnecessary table capabilities
from browser roles/defaults, narrows readiness UPDATE to an active global
coordinator with an active athlete-specific assignment, protects identity/score
columns, and revokes browser role-assignment RPC execution.

It preserves existing unrelated DML grants, service_role capabilities on existing
objects, existing function bodies/actor checks, profile self-service, audit
submission, current data, and consent predicates. The new helper explicitly
denies inherited/default PUBLIC, anon and service_role execution; authenticated
can use it through stored RLS expressions without adding private-schema USAGE.

This is production-adapted SQL, not the staging script: production's broad
table/default/function ACLs and private schema without client USAGE are modeled.
There are no staging/test account markers or data modifications in the SQL.
The snapshot/rehearsal contains no copied production user data.

## Reproduce safely in isolation

Install the pinned test dependency outside the application checkout. Do not
modify the application dependencies or lockfile:

```sh
npm install --prefix /tmp/sriq-production-pg17 --ignore-scripts --no-audit --no-fund @electric-sql/pglite@0.3.14
SRIQ_PGLITE_MODULE=file:///tmp/sriq-production-pg17/node_modules/@electric-sql/pglite/dist/index.js node db/proposals/production/test_production_permissions.mjs
```

The harness sets a project-marker GUC only inside its disposable local engine.
The SQL draft deliberately does not set its own opt-in marker. That marker is
an accident guard, not proof of project identity, user approval, backup
readiness, or a safe release artifact. Production execution still requires
explicit connector selection, refreshed baseline review and separate authorization.
Any PostgreSQL version, policy or ACL drift must stop execution and trigger
re-review rather than bypassing the guard.
